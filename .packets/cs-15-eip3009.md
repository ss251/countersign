# cs-15-eip3009 — the eip3009 rail: direct USDC on Arc testnet with transferWithAuthorization (refs #19)

## Setup

Run `bun install` at the worktree root before anything else.

## Goal

PLAN row 10: a direct-USDC rail. The buyer signs an EIP-3009 `TransferWithAuthorization` straight to the seller. The hub checks it and submits it with its relayer, so the buyer pays no gas. The money lands in one Arc block, before the work is dispatched, like the gateway rail and unlike escrow. It is x402's standard `exact` EVM scheme, under the USDC token's own EIP-712 domain.

## Facts, read live on Arc testnet on 06 Nov

- USDC is `0x3600000000000000000000000000000000000000`, with 6 decimals.
  - `name()` is "USDC" and `version()` is "2". It reverts with `FiatTokenV2: invalid signature`, so it is Circle's FiatToken v2.
  - The EIP-712 domain is `{name: "USDC", version: "2", chainId: 5042002, verifyingContract: 0x3600…0000}`.
- It has `transferWithAuthorization(address from, address to, uint256 value, uint256 validAfter, uint256 validBefore, bytes32 nonce, uint8 v, bytes32 r, bytes32 s)`, and the same function with `bytes signature` in place of `v, r, s`.
- It has `authorizationState(address authorizer, bytes32 nonce) returns (bool)`.
- The typehash is `TransferWithAuthorization(address from,address to,uint256 value,uint256 validAfter,uint256 validBefore,bytes32 nonce)`.
- The gateway rail also uses scheme `exact` on `eip155:5042002` with the same USDC asset. Its `extra.name` is `GatewayWalletBatched`, while this rail's `extra` is `{name: "USDC", version: "2"}`.

## What to build

### 1. `eip3009Rail(cfg)`, in `packages/rail/src/eip3009/index.ts`

`cfg` is `{id: "eip3009", chainId, rpcUrl, token, tokenName, tokenVersion, symbol, decimals, explorerTx, submitter, maxTimeoutSeconds?}`.

- **Declaration:** `kind: "direct"`, `scheme: "exact"`, `gasPaidBy: "hub"`, and `finality: "Final in the Arc block that includes the transfer, before the work is dispatched."`.
- **`challenge`** gives one `exact` entry:
  - `network: "eip155:<chainId>"`, `amount` set to the price in token units, `asset` set to the token, `payTo` set to the offer's seller payee (exactly as the gateway rail does), and `maxTimeoutSeconds`;
  - `extra: {name: tokenName, version: tokenVersion}`.
- **`verify`** decodes `payload: {signature, authorization: {from, to, value, validAfter, validBefore, nonce}}` and refuses with a plain `invalidReason` unless all of these hold:
  - `to` equals `payTo`, case-insensitively;
  - `value` equals `amount` exactly;
  - `validAfter <= now`, and `now + 6 <= validBefore <= now + maxTimeoutSeconds + 30`;
  - the EIP-712 signature under the token domain recovers to `from`;
  - `authorizationState(from, nonce)` is false on chain;
  - `balanceOf(from) >= value`.

  On success it returns `{isValid: true, payer: from}`.
- **`settle`** submits `transferWithAuthorization` in the `v, r, s` form from `submitter` and waits for the receipt, with the same timeout and "pending" handling as escrow.
  - Success needs a successful receipt that contains the token's `Transfer(from, to, value)` log.
  - Otherwise it returns `success: false` with an `errorReason`.
  - The settle result's `transaction` is the tx hash and `network` is the CAIP-2 network.

### 2. Hub wiring (`apps/hub/src/rails.ts`)

`EIP3009_RAIL=1`, together with `ARC_RPC_URL` and `CS_RELAYER_KEY`, adds:

```
eip3009Rail({id: "eip3009", chainId: 5042002, rpcUrl: ARC_RPC_URL, token: ARC_USDC, tokenName: "USDC", tokenVersion: "2", symbol: "USDC", decimals: 6, explorerTx: "https://explorer.testnet.arc.io/tx/{tx}", submitter})
```

If the flag is set but either variable is missing, log one line and leave the rail off. Never throw at boot.

### 3. Hub option matching (`apps/hub/src/call.ts`)

Two rails can now share scheme and network. A payment matches an option only when all of these are equal:

- `scheme` and `network`;
- `asset` and `payTo`, case-insensitively;
- `extra.name`, when either side has one.

If no option matches, answer as today ("This offer does not take that rail."). Add `apps/hub/test/eip3009.test.ts` with an offer that takes both gateway and eip3009, using fake rails, and check that each payment reaches its own rail.

### 4. Buyer

- **`known-rails.ts`** gains `KnownDirect {network, chainId, asset, name, version}` and `KNOWN_DIRECTS`, which holds Arc testnet USDC as above.
- **`terms.ts` `checkDirectTerms(offer, entry, known)`** refuses unless:
  - scheme, network and asset match a pinned direct and `extra.name/version` equal its pins;
  - `payTo` equals the offer's seller payee;
  - `amount` equals the offer price in token units;
  - `maxTimeoutSeconds <= 300`.
- **`payer.ts` `eip3009Payer(account, known = KNOWN_DIRECTS)`.** `canPay` holds only for a pinned direct entry. `pay` signs `TransferWithAuthorization` with:
  - a random 32-byte nonce;
  - `validAfter = now - 5` and `validBefore = now + min(maxTimeoutSeconds, 300)`;
  - the pinned domain, never the entry's.

  It returns the x402 `exact` payload, with `jobId = nonce`.
- **`buy.ts`.** An `exact` entry whose `extra.name` is `GatewayWalletBatched` stays on the gateway path. An `exact` entry that matches a pinned direct goes through `checkDirectTerms` and `eip3009Payer`. Nothing else changes in `buy()`.
- **`cli.ts`.** `--rail eip3009` restricts the choice, as `--rail gateway` does today.

### 5. Docs

Add an eip3009 section to `docs/spec/rail.md`: the domain, what the hub checks, who pays gas, and that this rail settles before delivery, so a failed delivery is not refunded automatically.

## Tests (anvil only, never a public RPC)

**`packages/rail/test/eip3009.test.ts`**, on anvil with the mock token, set up the way `escrow.test.ts` does:

1. A signed authorization verifies, settles, moves exactly `value` from buyer to seller, and the submitter pays the gas.
2. Replaying the same payload after settle fails verify, because the nonce is used.
3. A wrong `to`, a wrong `value`, an expired `validBefore`, a `validAfter` in the future, a signature by another key and a balance that is too low each fail verify, and no transaction is sent.
4. `settle` on a reverted transfer returns `success: false`.

**`packages/buyer/test/eip3009.test.ts`:**

- `checkDirectTerms` refuses a different asset, a domain name other than "USDC", a different `payTo`, a different amount and a `maxTimeoutSeconds` of 301.
- `eip3009Payer` signs under the pinned domain even when the entry's `extra` names another.
- Through a fake hub (as in `buy.test.ts`), `buy()` chooses eip3009 when it is the only option, and the gateway path when `extra.name` is `GatewayWalletBatched`.

**`apps/hub/test/eip3009.test.ts`:** as in item 3.
