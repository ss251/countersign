## What was built

### Rail — `packages/rail/src/eip3009/index.ts`

- `eip3009Rail(cfg)` declares `id: "eip3009"`, `scheme: "exact"`, `kind: "direct"`, `gasPaidBy: "hub"` and the required finality sentence.
- `challenge` returns one `exact` entry: `eip155:<chainId>`, the price in token units, the token address, `offer.payTo.eip3009 ?? offer.seller`, a payment window (config `maxTimeoutSeconds`, default 300), and `extra: {name: tokenName, version: tokenVersion}`.
- `verify` decodes `{signature, authorization}`, then refuses unless the payee matches case-insensitively, the value equals the amount exactly, `validAfter <= now`, `now + 6 <= validBefore <= now + maxTimeoutSeconds + 30`, the EIP-712 signature under the token domain recovers to `from`, `authorizationState(from, nonce)` is false, and `balanceOf(from) >= value`. Success returns `{isValid: true, payer: from}`.
- `settle` re-verifies, parses the signature into `v, r, s`, and submits `transferWithAuthorization` from the configured submitter through the same single-sender queue as escrow. Receipt waits use the escrow timeout and `"pending"` result. Success additionally requires the token's `Transfer(from, to, value)` log; a revert, estimation failure or missing log returns `success: false`.
- `packages/rail/src/index.ts` exports the new module.
- `contracts/test/mocks/MockEIP3009.sol` gains `transferWithAuthorization` (the `v, r, s` form) and its typehash; `authorizationState` was already public on the mock.

### Hub

- `apps/hub/src/rails.ts`: `EIP3009_RAIL=1` with `ARC_RPC_URL` and `CS_RELAYER_KEY` pushes the eip3009 rail with Arc USDC, chain 5042002 and the relayer as submitter. A missing variable logs one line and leaves the rail off; a bad key is caught and logged. Boot never throws.
- `apps/hub/src/call.ts`: a payment now matches an option only when scheme, network, asset and payTo (addresses case-insensitive), and `extra.name` (when either side has one) agree. This keeps GatewayWalletBatched and USDC apart on the same network and asset. The amount check keeps its existing “price moved” answer.

### Buyer

- `known-rails.ts`: adds `KnownDirect`, `KNOWN_DIRECTS` (Arc testnet USDC, domain `{name: "USDC", version: "2"}`), `knownDirectFor` (network + asset + name + version) and `pinnedDirectFor` (network + asset only, for signing under the pin).
- `terms.ts`: `checkDirectTerms` refuses an unknown direct, a different payee, a different amount, or a window over 300 seconds.
- `payer.ts`: `eip3009Payer(account, known)` signs `TransferWithAuthorization` with a random 32-byte nonce, `validAfter = now - 5`, `validBefore = now + min(maxTimeoutSeconds, 300)`, and the pinned token's domain. It returns the x402 `exact` payload with `jobId = nonce`.
- `buy.ts`: `exact` entries named `GatewayWalletBatched` stay on the gateway path; other `exact` entries go through `checkDirectTerms` and are recorded as rail `eip3009`. `railIdFor` recognises pinned direct entries so `--rail eip3009` filters correctly.
- `cli.ts`: the payer list includes `eip3009Payer`.

### Docs

`docs/spec/rail.md` gains the eip3009 table row and a section covering the domain, the hub's checks, who pays gas, and that settlement is final before delivery so a failed delivery is not refunded automatically.

## Tests

- `packages/rail/test/eip3009.test.ts` (anvil + real mock token): signed authorization verifies, settles and moves exactly the value while the submitter's account pays gas; replay fails after the nonce is used; wrong `to`, wrong `value`, too-short `validBefore`, future `validAfter`, wrong signer and zero balance all fail verify with no transaction sent; a transfer that expires before the block is mined returns a failed settle.
- `packages/buyer/test/eip3009.test.ts`: `checkDirectTerms` refusals for asset, name, payee, amount and a 301-second window; the payer signs under the pinned domain even when the entry names another; the payer caps the window at 300 seconds; a fake-hub `buy()` chooses eip3009 when it is the only option, keeps GatewayWalletBatched on the gateway path, and honours `rail: "eip3009"`.
- `apps/hub/test/eip3009.test.ts`: two fake `exact` rails share scheme/network/asset/payTo and differ only in `extra.name`; each payment reaches its own rail, and an unmatched name is refused as “This offer does not take that rail.”
